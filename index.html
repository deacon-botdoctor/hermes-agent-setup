The pipeline

One tree in, one verified tree out.

Every deploy runs the same five stages. Nothing reaches a runtime that has not been rehearsed against the exact upstream version it will land on.

SOURCE
Pristine upstream
A clean checkout pinned to an exact version. Your baseline and fallback.
MANIFEST
Registry
registry.yaml plus one module per patch. The single source of what you change.
BUILD
Apply
apply-all-patches overlays the registry onto the pristine tree, marker by marker.
VERIFY
Rehearse
Re-apply against a fresh version in a sandbox. Zero anchor-miss, or it does not ship.
SHIP
Deploy
One host at a time. Apply, restart, verify, receipt. No push-to-all.

A patch that fails to re-apply is caught in Rehearse, in a sandbox, before any runtime sees it. That is the whole reason a bump stays boring.

The reply rules

Why a client can run it unattended.

The message-quality layer is the point of the bundle. It lives in config and the immersion plugin, not in patches, so it is durable and drag-and-drop.

config

No streaming, no chatter

streaming: false, rich_messages: false, and notifications.tool_step_intermediate: false so a client gets one clean composed reply, never token-by-token or a stream of tool-step pings.

immersion plugin · transform_llm_output

Clean outbound

Strips internal continuity notes, suppresses interrupted-waiting placeholders, and masks provider/model failures behind one generic line. A client never sees the machinery.

immersion plugin · llm_request

Tool mute (context side)

Elides stale oversized tool results from history and drops orphan tool calls, so huge file reads do not dominate the window every turn.

Triage rule

Before any change, walk the ladder.

Take the highest rung that fits. Higher is cheaper to own. The bottom rung is where the bleeding is.

DELETEIs it even wanted? Upstream may already do it. Cut it.
CONFIGIs there a knob? Set it, move on.
PLUGINIs there a seam? Attach a plugin. It survives bumps.
UPSTREAMGenerally useful? Send it upstream.
SIDECARExternal script. Touches no upstream file.
PATCHLast resort. A source edit anchored to upstream lines. Needs a reason and a retirement condition.

Plugins

Anything with a seam does not get a patch.

memory provider

Long-term recall

Remembers durable facts and prior work across sessions. Hooks the turn cycle to write and prefetch. A first-class extension point.

register_platform

Adapter override

A thin subclass of the bundled chat adapter. Same-key registration replaces it, so you override a few methods and inherit the rest. Override methods, do not fork files.

output hooks

Immersion

Acknowledge input while working, emit status. Output and lifecycle transforms are exactly what the hook seams are for. Check config first.

Config

The keys you change, and why.

config.yaml · the edits that matter
durable_runtime: true              # survive restarts without losing work
redaction: {enabled: true}       # non-negotiable
rich_messages: false             # plain output on chat lanes
input_mode: queue               # a new message waits, does not kill the turn
compression: {codex_gpt55_autoraise: true}  # off drops compaction to ~25%
notifications: {policy: quiet-exception-only}
skills: {index_allowlist: [<core-1>, <core-2>]}
model: {primary: <primary>, fallback: [<cheap>, <capable>]}

Every value is a placeholder. Nothing here is a secret. The redaction key is first for a reason: secrets in tool output otherwise persist to the transcript and get re-sent every turn.

Build order

Stock first. Add only what maps to a real problem.

Get stock working, unmodified

A plain agent on your platform, zero customization. This is how you tell scar tissue from a real need.

Config pass

Go key by key against the default. redaction first, then durable runtime and queue mode.

Stand up the registry

Create registry.yaml and one module per patch. Add only the rows whose problem you actually have.

Plugins for anything with a seam

Memory, platform override, output hooks. Prefer a plugin over a patch every time a seam exists.

Apply, then rehearse

apply-all-patches onto pristine, then rehearse against the target version. Zero anchor-miss before you ship.

Deploy host by host

Apply, restart, verify, receipt. Propagate one at a time. There is no safe push-to-everything.

the loop, in commands
apply-all-patches --hermes-dir ./runtime      # build the overlaid tree
rehearse --tag v-next --against ./runtime     # sandbox verify, 0 anchor-miss
deploy --host one-runtime && verify && receipt # then the next host
